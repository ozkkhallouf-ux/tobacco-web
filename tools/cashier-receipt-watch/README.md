# مراقب إيصالات الكاشير بعد الطباعة

يكشف كل إيصال كاشير لم يعد يطابق فاتورته الحالية في الأمين، ويرسل تنبيه تيليغرام مجمّعاً.
**لا يعيد الطباعة أبداً، ولا يكتب في الأمين.**

## لماذا

تدقيق 2026-11-12 بسجل عمليات الأمين (`log000`) أثبت أنه من 2,175 إيصالاً طبعها الجسر:
- **333 فاتورة عُدّلت بعد الطباعة** بتغيير ظاهر على الإيصال: أصناف مضافة أو محذوفة، كميات، أسعار وحدة، خصم أو إضافة، صافي.
- **26 فاتورة حُذفت بعد الطباعة**، منها حالات أُعيد إدخالها برقم جديد (#2991 ← #2992).
- **الأمين يعيد استخدام الرقم بعد الحذف** (#2989 يوم 11-11 ثم لفاتورة أخرى يوم 11-12)، فالرقم وحده لا يميّز.

## ما يفعله في كل تشغيل

1. يقرأ الأرشيف الثابت الذي يكتبه الجسر (`C:\ProgramData\OZK-TOBACCO\ReceiptArchive`، الوحدة
   `ozk-print-bridge/OzkReceiptArchive.psm1`).
2. **دليل Windows:** يطابق حدث `PrintService/Operational 307` برقم المهمة والطابعة والوقت، ويسجّل
   المرحلة `windows_completed`. هذا ليس دليلاً على خروج الورق: المرحلة `paper_confirmed` لا يكتبها إلا
   دليل مستقل صريح.
3. يقارن آخر إيصال وصل Windows لكل GUID بالفاتورة الحالية. المقارنة **من القيم الخام بنفس تحويل الجسر**:
   الكمية بالوحدة المختارة، والمبلغ ÷ `CurrencyVal`.
   - تعديل ظاهر ⇒ `edited`. تغيّر سعر الصرف وحده بلا تغيّر في المطبوع **لا يُبلَّغ**.
   - غياب مع سجل حذف (`log000` OperationType=2) ⇒ `deleted`. غياب بلا سجل ⇒ `missing_unexplained`،
     ولا يُفترض الحذف.
   - لم تعد كاشير مرحّلة ⇒ `no_longer_cashier_posted`.
   - مرشح إعادة إدخال: فاتورة كاشير حالية قريبة الإنشاء، تتداخل أصنافها بنسبة 50% على الأقل.
   - الرقم صار لفاتورة أخرى ⇒ تحذير صريح.
4. **نتيجة مجهولة:** إيصال جُهِّز وأُرشف، ومرّت 10 دقائق بلا تسليم ولا فشل مسجَّل. السبب انقطاع بين
   الأرشفة والطباعة أو بعد التسليم وقبل تسجيله. الجسر لا يعيد طباعته آلياً (منعاً للتكرار)، فيُطلب التحقق
   يدوياً. ولا يُبلَّغ إن طُبعت الفاتورة نفسها لاحقاً.
5. ينبّه برسالة واحدة مجمّعة (حتى 10 فواتير؛ الباقي في التالية)، **بلا اسم زبون**، ومع منع التكرار:
   كل فاتورة تُبلَّغ مرة واحدة لكل حال مختلفة.
6. **أول تشغيل يسجّل نقطة البداية فقط** (`watchStartUtc`). لا تنبيهات عن أي إيصال طُبع قبلها:
   لا رسائل تاريخية جماعية.

## التشغيل

```
powershell -NoProfile -ExecutionPolicy Bypass -File tools\cashier-receipt-watch\cashier-receipt-watch.ps1 -DryRun
```

| الوسيط | المعنى |
|---|---|
| `-DryRun` | لا كتابة إطلاقاً (لا حالة ولا مراحل ولا تيليغرام)، ويطبع الرسالة |
| `-NoTelegram` | يحدّث الحالة والمراحل بلا إرسال |
| `-LookbackHours` | نافذة الفحص (الافتراضي 72) |
| `-ConnectionEnvVar` | متغيّر سلسلة اتصال القراءة (الافتراضي `AMEEN_SQL_CONNECTION_STRING`) |

- **سلسلة الاتصال:** تُرفض إن كانت `sa`، أو كان الحساب يملك `sysadmin` أو `db_owner` أو `db_datawriter`.
- **الاستعلامات:** كل استعلام يمر بحارس SELECT فقط، بمعاملات بلا دمج نصي.
- **الحالة:** في `ReceiptArchive\watch\state.json`.

**غير مسجَّل كمهمة مجدولة بعد.** التسجيل (كل 5 دقائق، بهوية OZKKH) والنشر على OZKUSER بموافقة عمر فقط.
