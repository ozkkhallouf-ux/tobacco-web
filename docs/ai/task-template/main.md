## سير العمل المعتمد

1. **Claude | التحليل والتشخيص:** افحص المشكلة أولاً، حدّد السبب الجذري والمخاطر، واقترح خطة واضحة. لا Merge ولا Deploy.
2. **Cursor | التنفيذ:** راجع تحليل Claude وافحص الكود الفعلي. نفّذ الحل بأقل نطاق آمن على فرع مستقل، شغّل الاختبارات، وافتح Pull Request. لا Push مباشر إلى `main` ولا Merge ولا Deploy.
3. **Codex | المراجعة المستقلة:** راجع التغييرات والاختبارات على HEAD الحالي للـPR، وابحث عن regressions ومشاكل المنطق والأمان. إذا ظهرت ملاحظة، تعود إلى Cursor للإصلاح ثم تعاد المراجعة.
4. **GitHub | التتبع:** يُستخدم لتتبع الـPR والفحوص والتعليقات والمراجعات.
5. **Omar | القرار النهائي:** لا Merge ولا Deploy حتى تصدر موافقة صريحة من Omar على الـPR المحدد.

## قواعد OZK الإلزامية

- اجعلوا النقاش الخاص بالمهمة داخل Thread واحد قدر الإمكان.
- لا يعمل أكثر من Agent على نفس الملفات بالتوازي دون تنسيق واضح.
- ممنوع Push مباشر إلى `main`.
- ممنوع Merge أو Deploy تلقائي.
- ممنوع Admin Bypass.
- لا تغييرات خطرة أو مدمرة على Production DB دون موافقة صريحة.
- لا تعرضوا أو تنسخوا Secrets أو Tokens أو كلمات مرور.
- تكامل Ameen Live يبقى Read Only.
- لا تعتبر المهمة مكتملة قبل نجاح الاختبارات المطلوبة ووصول مراجعة Codex على HEAD الحالي.
- تبقى تنبيهات Telegram الحالية كما هي ما لم يطلب Omar تغييرها صراحة.
