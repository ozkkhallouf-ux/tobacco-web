# تعاون Slack وGitHub والوكلاء

آخر تحديث: 2026-09-16

## الحالة الحالية

Slack مثبت على Mac Mini وهو مركز العمليات والإشعارات. التطبيقات الرسمية مربوطة: GitHub وCursor وCodex وClaude. المستودع لا يحتوي كود Slack ولا webhook ولا سر إشعار.

قنوات التوجيه العربية قائمة:

| القناة | الدور |
|---|---|
| `#تطوير-ozk` | بدء المهام، ثريدات الوكلاء، إشعارات GitHub للـPR والمراجعات والتعليقات |
| `#تنبيهات-ozk` | تنبيهات تشغيلية (تطبيق Cursor غير عضو فيها حالياً) |
| `#قرارات-ozk` | قرار الدمج/النشر من عمر (تطبيق Cursor غير عضو فيها حالياً) |

في `#تطوير-ozk` تم: إضافة GitHub، الاشتراك في `pulls` و`reviews` و`comments` للمستودع `ozkkhallouf-ux/tobacco-web`، و`@Cursor settings` على المستودع نفسه وفرعه الافتراضي.

GitHub هو مصدر الحقيقة الوحيد للكود والفروع والـPR وفحوص CI والمراجعة وحالة الدمج.

المسار المعتمد:

```
عمر → Slack (#تطوير-ozk، ثريد واحد) → Cursor / Codex / Claude → فرع GitHub → PR → CI + اختبارات → Codex Review Gate → رابط PR في الثريد → توقف بانتظار موافقة عمر → دمج / نشر
```

فحوص `main` المطلوبة حياً (ruleset `21808376` `main-protection-with-admin-bypass`): `Codex Review Gate`، `check`، `validate`، `critical-journeys`، `توافق Windows PowerShell 5.1`. حل محادثات المراجعة مطلوب. عدد المراجعات البشرية المطلوبة حالياً = 0. حساب Admin يستطيع تجاوز القواعد — **ممنوع استعمال التجاوز**. الدمج في `main` يطلق نشر GitHub Pages عبر `pages.yml`؛ لا دمج ولا نشر بدون أمر صريح من عمر.

تنبيهات فشل الأتمتة تبقى عبر Telegram (`alert-on-automation-failure.yml` → `notify_telegram`). Slack لا يستبدل هذا المسار ولا يُضاف له workflow webhook مخصص.

قفل التنسيق (`AI_ACTIVE_TASK.json` + `tools/ai-work-coordination.ps1`) ما زال الاستثناء التنظيمي الوحيد الذي يُنشر مباشرة على `main`. مالكو القفل: `Claude` و`Codex` و`Human` و`Cursor`. بروتوكول الحجز على `main` لم يتغيّر.

Mac Mini جهاز عميل Slack ومرافق محلية فقط؛ ليس هدف تشغيل جديد للمنتج ولا يوسّع دعم macOS خارج النطاق المبوَّب في `AGENTS.md`.

## ظهور الرسائل في `#تطوير-ozk`

هذا هو السلوك المثبت، وليس ما يُتوقع من اسم الاشتراك وحده:

| المصدر | أين يظهر | متى يظهر | ماذا لا يظهر |
|---|---|---|---|
| مهمة عمر | رسالة في القناة، والردود في ثريدها | عند النشر اليدوي | لا شيء تلقائي |
| Cursor / Claude / Codex | ردود داخل ثريد المهمة التي ذُكروا فيها | أثناء التشغيل وعند التسليم (حالة، ملخص، رابط PR) | لا رسالة قناة جديدة إذا بدأ العمل من محادثة Cursor خارج هذه القناة |
| GitHub (`pulls`) | رسالة قناة | PR جاهز للمراجعة أو دُمج أو أُعيد فتحه | فتح المسودة لا يُرسل إشعاراً. مسودات وكلاء Cursor غالباً تبقى صامتة حتى Ready for review |
| GitHub (`reviews`, `comments`) | رسالة قناة أو رد على إشعار الـPR | عند المراجعة أو التعليق | لا يغطي تعليقات وكلاء بدأت خارج GitHub |
| GitHub CI | لا يظهر حالياً | يحتاج `/github subscribe ozkkhallouf-ux/tobacco-web workflows` من عمر في القناة | فحوص `check` / `validate` / البوابة لا تصل Slack اليوم |

قواعد الظهور المعتمدة داخل القناة:

1. كل مهمة ثريد واحد. لا تُفتح محادثة وكيل جديدة خارج القناة إذا كان المطلوب أن يراها الجميع هنا.
2. املأ قالب بدء المهمة، ثم اذكر الوكيل **داخل الثريد**. ذكر كل الوكلاء في رسالة القناة يشغّلهم معاً على نفس الموضوع.
3. الوكيل ينشر رابط الـPR في الثريد. لا يُعتمد على إشعار GitHub وحده لأن المسودات صامتة.
4. عندما يصبح الـPR جاهزاً لمراجعة عمر: يُرفع من مسودة إلى Ready for review حتى يحاول GitHub إشعار القناة.
5. الرسائل قصيرة وعربية وMarkdown. بلا أسرار وبلا لصق سجلات طويلة في القناة.
6. تثبيت رسالة القالب بدبوس يتم يدوياً من عمر؛ الوكلاء لا يستطيعون التثبيت.
7. **ثبات الجلسة (ثريد واحد = تشغيل واحد لكل وكيل):** انظر القسم التالي — لا تعتمد على منشن جديد بعد انتهاء الجلسة دون اتباع قواعد كل منتج.

## ثبات الجلسة في `#تطوير-ozk` (Cursor / Claude / Codex)

الهدف التشغيلي: من القناة تتكلم مع كل وكيل **فيكمل نفس الجلسة/الثريد**، ولا يفتح شغلاً جديداً يشتّت الفرع والـPR.

هذا **سلوك منتجات Slack** (Cursor / Anthropic / OpenAI)، وليس شيئاً يُصلَح من كود `tobacco-web`. المستودع يثبّت البروتوكول فقط؛ تفعيل Claude Tag إعداد Owner في Claude.

### Cursor (`@Cursor`)

| افعل | لا تفعل |
|---|---|
| رد **داخل ثريد الوكيل** بـ `@Cursor …` لإضافة متابعة على **نفس** Cloud Agent | رسالة قناة جديدة بنفس المهمة (يفتح وكيلاً جديداً) |
| استخدم المتابعة العادية | `@Cursor agent …` أو عبارات «start a new / fresh agent» إلا إذا أردت وكيلاً ثانياً عمداً |
| إن وُجد أكثر من وكيل في الثريد: ⋯ على رسالة الوكيل → **Add follow-up** | حذف الوكيل من القائمة أثناء العمل |

- إعداد القناة: `@Cursor settings` في `#تطوير-ozk` (مستودع افتراضي = `tobacco-web`).
- إن احتاج الزملاء متابعة وكلاء بعضهم: Dashboard → Cloud Agents → **Team Follow-ups** = `All` (أو حسب سياسة الفريق).
- المرجع: [Cursor Slack](https://cursor.com/docs/integrations/slack).

### Claude (`@Claude`) — السبب الجذري لفتح «محادثة ثانية»

البوت الحالي على القناة ما زال **Legacy** (يظهر الشريط: *Using the legacy Claude in Slack bot… enable Claude Tag*). تحت Legacy كل منشن بعد انتهاء الجلسة يفتح **جلسة Code جديدة** حتى لو الرد في نفس ثريد سلاك.

| الحل | من ينفّذه | أين |
|---|---|---|
| تفعيل **Claude Tag (New)** على مساحة العمل / نطاق `#تطوير-ozk` | Owner في Claude (عمر) | `claude.ai/admin-settings/claude-tag` |
| ربط GitHub لـ Claude Tag (الروابط الشخصية لا تنتقل) | Owner | نفس لوحة Claude Tag → connections / access bundles |
| بعد التفعيل | الفريق | الرد في الثريد يوجّه **نفس الجلسة المستمرة لكل ثريد**؛ غالباً بلا إعادة منشن أثناء العمل الجاري |

مرجع Anthropic: [Migrate from earlier Claude in Slack](https://claude.com/docs/claude-tag/admins/migrate-from-earlier) — جدول المقارنة: Legacy = جلسة لكل طلب؛ New = جلسة واحدة مستمرة لكل ثريد.

حتى يكتمل التفعيل: لا تعتمد على منشن بعد «session is complete»؛ استخدم **View session** قبل الإغلاق، أو اقبل جلسة جديدة واذكر صراحة رقم الـPR/الفرع.

### Codex (`@Codex`)

`@Codex` في سلاك للأسئلة/الرأي الثاني لا للتنفيذ إلا بطلب عمر. أبقِ المراجعات في **نفس ثريد المهمة** أو على GitHub على HEAD الحي؛ لا تفتح ثريد Codex منفصلاً لنفس الـPR إلا لسؤال مستقل.

### بروتوكول عمر المختصر (ثبّته بدبوس إن أمكن)

```
1) مهمة واحدة = رسالة قناة واحدة + ثريد واحد.
2) داخل الثريد: @Cursor / @Claude / @Codex حسب الدور — لا تجمعهم كلهم في أول رسالة إلا إذا أردت تشغيلهم معاً.
3) المتابعة دائماً رد في نفس الثريد مع منشن الوكيل المعني (Cursor: بدون كلمة agent).
4) Claude: بعد تفعيل Claude Tag، الرد في الثريد يكفي لتوجيه الجلسة؛ قبل ذلك View session أو منشن + ذكر PR.
5) ممنوع رسالة قناة جديدة لنفس المهمة.
```

أمر GitHub المتبقي (يدوي من عمر في `#تطوير-ozk` إن أراد حالة CI هنا):

```
/github subscribe ozkkhallouf-ux/tobacco-web workflows
```

أول مرة قد يطلب GitHub صلاحيات إضافية لـActions. الاشتراك اختياري؛ الضوضاء واردة.

## قيود ثابتة

- لا دفع مباشر إلى `main` إلا استثناء قفل/تسليم التنسيق القائم.
- لا إضعاف لحماية الفرع ولا استعمال admin bypass ولا دمج آلي ولا نشر آلي من الوكلاء.
- لا تعديل بيانات قاعدة الإنتاج. الأمين الحي للقراءة فقط.
- لا أسرار في Git أو Slack أو قوالب الـPR.
- Cursor ينفّذ على فرع ويفتح PR عند التكليف الصريح؛ لا يدمج ولا ينشر.
- Codex طبقة مراجعة مستقلة عبر البوابة الحالية على HEAD SHA الحي للـPR. `@Codex` في Slack للأسئلة/الرأي الثاني لا للتنفيذ إلا بطلب عمر.
- Claude Code وكيل ثانوي للتشخيص والرأي المستقل؛ جلسة ويب واحدة → PR واحد كحد أقصى؛ لا دمج.
- لا تثبيت Actions أو حزم طرف ثالث لمسار Slack. التكاملات الرسمية فقط.
- لا إنشاء سر `SLACK_WEBHOOK` من المستودع.
- وكيل Cursor لا يشغّل أوامر `/github` ولا يثبّت الرسائل؛ ذلك يدوي من عمر.

## فحوص إلزامية

`npm run check`، `git diff --check`، ومراجعة أن الـPR لا يلمس workflows الحماية أو النشر أو Telegram. الدمج ممنوع حتى يخضر CI وبوابة Codex على **HEAD الحالي** ويوافق عمر صراحة.
